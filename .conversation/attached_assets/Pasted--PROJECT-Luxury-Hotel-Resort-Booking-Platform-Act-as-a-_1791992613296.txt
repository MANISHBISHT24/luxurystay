# PROJECT: Luxury Hotel & Resort Booking Platform

Act as a senior full-stack developer, UI/UX designer, backend engineer, database architect, QA engineer, and application security specialist.

Build a complete, production-oriented hotel and resort booking website with a premium, elegant, responsive design. The website must include a functional frontend, backend APIs, database, authentication, room availability management, online payments, customer dashboard, and secure admin panel.

Do not build only a static frontend. Implement the complete working application and connect all features to the backend and database.

## 1. TECHNOLOGY STACK

Use the following stack:

- Frontend: Next.js with App Router, React, TypeScript
- Styling: Tailwind CSS and reusable UI components
- Backend: Next.js server-side route handlers and server actions where appropriate
- Database: PostgreSQL
- ORM: Prisma
- Authentication: Auth.js or another well-maintained authentication solution
- Validation: Zod
- Forms: React Hook Form
- Payments: Razorpay for INR payments, with server-side payment verification
- Email: Resend or SMTP
- Image storage: S3-compatible storage or Cloudinary
- Testing: Vitest and Playwright
- Deployment: Vercel or a suitable Node.js hosting platform, with managed PostgreSQL

Use stable, mutually compatible package versions. Keep secrets in environment variables and never expose them to the browser.

## 2. BRANDING AND UI/UX DESIGN

Create a premium hotel and resort brand with a memorable, configurable name and logo.

Design direction:
- Elegant cream, white, warm beige, forest green, and subtle gold
- Large high-quality hotel, room, restaurant, and landscape photography
- Modern typography with generous spacing
- Premium editorial-style layouts
- Subtle animations and transitions
- Rounded cards and refined buttons
- Consistent spacing, colors, shadows, and typography
- Mobile-first responsive design
- Accessible navigation and keyboard interactions

Avoid generic templates, excessive gradients, cluttered layouts, and unnecessary animations.

## 5. ROOM MANAGEMENT AND SEARCH

Each room type should support:

- Room category
- Images and image gallery
- Maximum occupancy
- Bed configuration
- Room size
- Amenities
- Base price per night
- Seasonal pricing
- Taxes and additional charges

- Published/unpublished status

Implement filtering by dates, guest capacity, room category, price range, and amenities.

Show accurate availability and a transparent price breakdown. Prevent overbooking, including when multiple customers attempt to reserve the last available room simultaneously.

## 6. COMPLETE BOOKING FLOW

Implement this booking process:

1. Customer chooses check-in and check-out dates.
2. Customer selects guests and rooms.
3. Backend checks room availability.
4. Website displays available room options.
5. Customer selects a room and enters guest information.
6. Backend calculates the price, taxes, discounts, and total.
7. Customer reviews the booking summary.
8. Backend creates a pending booking with an appropriate inventory hold.
9. Customer completes payment through the payment provider.
10. Backend verifies payment authenticity.
11. Booking is confirmed only after verified payment or an explicitly configured legitimate payment method.
12. Confirmation page displays the booking reference.
13. Confirmation email is sent.
14. Booking inventory and status are updated safely.

Handle failed payments, expired holds, duplicate requests, abandoned checkout, cancellations, and payment retries.

Use database transactions, appropriate locking or atomic inventory updates, and idempotency controls to avoid duplicate bookings and overselling.

## 7. DATABASE DESIGN

Design a normalized PostgreSQL schema using Prisma.

Include appropriate models for:

- User
- Account and Session if required by the authentication provider
- Hotel or Resort
- RoomType
- RoomInventory or RoomUnit
- SeasonalRate
- Booking
- BookingGuest
- Payment
- Refund
- Coupon
- Review
- Amenity
- RoomTypeAmenity
- Image
- ContactMessage
- NewsletterSubscriber
- AuditLog

Add primary keys, foreign keys, indexes, unique constraints, appropriate data types, timestamps, and relationships.

Use explicit booking statuses such as PENDING_PAYMENT, CONFIRMED, CANCELLED, and EXPIRED, with a documented transition policy.

Store monetary values using a precise decimal representation or integer minor units. Never use floating-point arithmetic for financial calculations.

Create migrations, realistic seed data, and instructions for setting up the database.

## 10. PAYMENT INTEGRATION

Integrate Razorpay in test mode first.

Requirements:

- Create payment orders on the server.
- Recalculate the booking total on the server.
- Verify payment signatures on the server.
- Verify webhook signatures and process webhook events idempotently.
- Handle successful, failed, pending, and duplicate payment events.
- Record transaction IDs and payment status.
- Support refunds through authorized server-side operations.
- Keep test and live credentials separate.
- Never store card numbers, CVVs, or other sensitive card data.
- Never confirm a booking solely because the frontend reports payment success.

Document the steps required to activate live payments.

## 17. IMPLEMENTATION RULES

Work in clear, verifiable phases:

Phase 1: Project structure, UI design system, and responsive frontend.

Phase 2: PostgreSQL schema, Prisma migrations, and seed data.

Phase 3: Authentication, authorization, and protected routes.

Phase 4: Room search, availability, pricing, and booking lifecycle.

Phase 5: Payment integration, webhooks, and email notifications.

Phase 6: Admin dashboard and reporting.

Phase 7: Security hardening, testing, SEO, and accessibility.

Phase 8: Deployment documentation and final verification.

Begin by inspecting the existing repository. If it is empty, initialize the project. If code already exists, preserve useful functionality and avoid unnecessary rewrites.

At each phase, implement real functionality, run the relevant checks, and fix errors. Do not leave core features as TODOs, fake API calls, hardcoded dashboard statistics, or nonfunctional buttons.

If a third-party credential is unavailable, build the integration safely, document the required configuration, and clearly identify what cannot be tested.

Start with the project structure and homepage, then continue through the complete application. Do not stop after creating a design mockup.

At completion, provide the implemented features, project structure, database setup commands, environment-variable instructions, test results, known limitations, and deployment steps.
